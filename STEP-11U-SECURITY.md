# Step 11U — Execution reconciliation and recovery foundation

## Scope and reason for reconciliation

Step 11T can leave an execution Reserved when cancellation, coordinator interruption, handler side effects, or uncertain store completion occurs. Reserved alone cannot tell whether the handler never started, was cancelled, completed, caused an external effect, or was durably completed without a returned acknowledgement. Step 11U provides **assessment only**. It neither retries a tool nor mutates execution state. There is no production reconciliation worker, source adapter, operator action, queue, outbox, or persistence implementation.

## Application boundaries and workflow

`ExecutionReconciliationRequest` contains only ActionId. It accepts no execution ID, reason, outcome, disposition, proof, free text, command, path, URL, output, log, or arbitrary metadata. `ActionScope` is a separate server-owned input. `IExecutionReconciliationScopeValidator` represents authenticated user, owned conversation, exact project association, and owned project; its supplied implementation denies all. `IExecutionReconciliationSource` returns an optional bounded `ExecutionReconciliationSnapshot` from a future trusted durable source; its supplied implementation always returns unavailable. `IExecutionReconciliationPolicy` provides a bounded advisory disposition; its supplied conservative implementation returns `NeedsManualReview`. None is registered as a production allow path.

`ExecutionReconciliationService.ReconcileAsync` validates the request and scope, validates ownership, obtains the snapshot, checks `ActionExecutionStatePolicy.IsValid`, validates the bounded reason and exact action/scope/tool/approval/execution/version consistency between snapshot and state, requires Reserved, runs the conservative policy, revalidates ownership, then issues immutable assessment evidence with a server UTC timestamp. Ready returns `NotEligible`; Succeeded and Failed return `AlreadyResolved`; malformed or mismatched data fails closed. The source must scope before reading and attest current state; IDs and approval alone are not ownership or reconciliation proof. The policy is advisory and does not grant execution or operator permission.

The reason enum is `ReservationCancelled`, `HandlerCancelled`, `HandlerCompletedButStateIncomplete`, `StoreCompletionUncertain`, `CoordinatorInterrupted`, and `Unknown`. The disposition enum is `NeedsManualReview`, `SafeToMarkFailed`, `AlreadyResolved`, and `Unavailable`. Unknown enum values fail closed. A synthetic test policy can return `SafeToMarkFailed`, but this step **still does not change Reserved to Failed**. No Succeeded recovery path exists. A future operator/manual recovery boundary and transactional Reserved-to-Failed transition, if justified, require separate design and authorization. Expiry is deferred.

`ExecutionReconciliationEvidence` has a private constructor and internal issuance. Its ID has a private constructor and internal server factory. Evidence carries only reconciliation ID, ActionId, exact ActionScope, ToolId, ApprovalId, ExecutionId, observed state/status and version, bounded reason and disposition, and server-issued UTC time. It contains no handler output, proof payload, secret, arbitrary text, path, or collection. It is neither execution proof, verification proof, permission, audit persistence, nor a database transaction guarantee.

## Safety limits

The service has no `IToolHandler`, dispatcher, `ITrustedToolExecutionService`, `IActionExecutionStateStore` mutation, or verification dependency. It cannot invoke or retry a tool, transition state, create a new execution ID, fabricate an `ActionDescriptor`, mark verified, or create a VerificationId. `ApprovalEvidence` remains immutable. Repeated assessment may issue another reconciliation ID because no durable consumption/single-use record is implemented. An execution success report or AI text is not proof of reconciliation. There is no automatic successful recovery or external side-effect inference.

All async boundaries accept `CancellationToken`, which propagates. Cancellation during assessment can leave Reserved state unchanged and produce no assessment; it never triggers a tool retry. Non-cancellation dependency failures map to fixed `Failed`, while unavailable source/policy returns `StateUnavailable`; malformed bindings return `StateConflict`. Results contain no raw exception or source data, and fixed messages are at most 80 characters. The request and evidence use fixed identifiers, three scope GUIDs, the existing bounded tool ID, one `long` version, enums, and one UTC time; there are no unbounded collections or arbitrary strings.

The package-free security checks cover eligibility, exact bindings, ownership and revocation, default denial/manual review, invalid enums, synthetic advisory disposition without mutation, cancellation, safe errors, immutable evidence, repeated assessments, unchanged chat/provider request surface, and no handler dependency. The synthetic source is in security-check code only. These checks do not establish production source trust, PostgreSQL consistency, side-effect knowledge, or distributed recovery.

No production database/reconciliation adapter, DbContext, EF configuration, schema, migration, package, background worker, real handler, shell/Git/filesystem/browser/HTTP/MCP execution, provider tool call, chat integration, or automatic verification is added. Safe File Access remains disabled. No real PostgreSQL, OpenAI, or Ollama call was made. Production ownership/source/policy behavior, PostgreSQL/pgvector runtime, real side effects, independent verification provenance, semantic retrieval/ranking, and live OpenAI/Ollama remain unverified. This is not exactly-once execution or production recovery readiness.
